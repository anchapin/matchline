# Construction library (#747)

Drawings rarely state U-values. `construction_library.py` resolves a wall-type
tag or roof note to the ASHRAE 90.1-2019 Table 5.5 maximum assembly value for
that construction class and climate zone, the way the space-use defaults (#685)
fill loads from the DOE prototypes.

## Source

`construction_library_data.py` is generated by
`scripts/build_construction_library.py` from
`ashrae_90_1_2019.construction_properties.json` in NREL openstudio-standards
v0.8.6 (the same tag as the space-use defaults). It holds Tables 5.5-0 to 5.5-8
for the Nonresidential, Residential and Semiheated categories. IP values are
copied verbatim; SI U- and C-factors use 1 Btu/h-ft2-F = 5.678263 W/m2-K.
F-factors stay in IP. No hand edits; re-run the script to regenerate.

## Rules

- A stated value (drawing, schedule, IFC ThermalTransmittance) is never
  overwritten. Only constructions with no U-value are filled.
- No climate zone, no fill. Pass `--climate-zone 4A` (or `climate_zone` in the
  YAML config); the zone is never assumed. Table 5.5 is split by zone number,
  so 4A, 4B and 4C use Table 5.5-4.
- A construction resolves only when its id or name names exactly one class:
  - walls: Metal Building (metal building, insulated metal panel), SteelFramed
    (steel/metal/light-gauge stud or framing), WoodFramed (wood stud, 2x6 stud),
    else Mass (CMU, concrete, masonry, brick, block, tilt-up, precast).
    Framing wins over cladding, so "brick veneer on metal stud" is SteelFramed.
    Two framing classes in one description is ambiguous and is not filled.
  - the roof (`roof_construction_id`): IEAD (insulation above deck), Metal
    Building (standing seam), Attic and Other (attic, wood joist or truss).
- Every filled value carries Provenance method `construction_default`,
  confidence 0.6, and a note naming the source, edition, table, category,
  construction class, climate zone and the words that matched. The value is
  the code maximum, not the drawn assembly.
- Unmatched constructions and a missing climate zone are reported in
  `stage_03b_constructions.json` and in `convention_report.json` under
  `constructions`.

IFC walls (#747): when a wall has no stated `ThermalTransmittance` and no U
can be derived from its layers, the import gives it an unset-U construction
`IFC-TYPE-<type name>` (provenance `ifc_import:tier0:wall_type`, confidence
0.5) if the wall's type name, or else its material layer names, names exactly
one class. The library then fills it like any drawn tag. Layers are read one
at a time with separators flattened (`Metal - Stud Layer` reads as metal
stud); a framing layer beside a mass layer (CMU with stud furring) is
ambiguous and stays unassigned, so the Table 5.5 unlabeled default still
reaches that wall. On the BSI Clinic, the 80 exterior walls
(`Exterior - Insul Panel on Mtl. Stud`, insulated panel and plywood have no
conductivity) now resolve as SteelFramed from their type name instead of the
blanket unlabeled default: same U, a named source.

Slab on grade (#747): an unset ground slab gets `t55-slab`, the Table 5.5
unheated-slab F-factor for the category and zone,
converted to SI (1 Btu/h-ft-F = 1.730735 W/m-K) and carried as an effective U:
F x exposed perimeter / slab area. Area and perimeter come from the footprint
of the lowest level's spaces; every slab edge counts as exposed. A stated slab
U is never replaced. A lowest level with no space polygons is reported, not
filled. The F-factor, perimeter, area and resulting U are written to
`stage_03b_constructions.json` under `defaulted`.

## Which table feeds what (#781)

1. Envelope thermal values stated on the drawings (or in IFC) are used as given.
2. Envelope the drawings leave unlabeled gets the Table 5.5 code maximum:
   walls with no construction get `t55-wall`, an unset roof `t55-roof`, an
   unset slab `t55-slab`. Table 5.5 needs a class and the drawings name none,
   so these use the classes Appendix G uses for its baseline (steel-framed
   wall, insulation entirely above deck). Their provenance says "no assembly
   stated on the drawings; Table 5.5 code maximum".
3. The Appendix G baseline uses 90.1-2019 Tables G3.4-1 to G3.4-8 (PRM 2019,
   `construction_library_prm_data.py`, generated by
   `scripts/build_prm_library.py` from openstudio-standards v0.8.6). The
   baseline set is written to `stage_03b_constructions.json` under `baseline`:
   wall, roof, slab (with its effective U on the model footprint), exterior
   floor, doors, vertical glazing, glass doors and skylights. Glazing picks
   its band from the model's window-to-wall and skylight-to-roof ratios; above
   40% WWR the top band is used (G3.1-5(c)). Zone 3 uses the 3A/3B/3C rows.
   The baseline set is recorded only; the exported model is the proposed
   design and is not changed by it.

Space wall U-values are rolled up again after filling, so gbXML and IFC4
exports carry the resolved values.

## Not yet

Windows, skylights and doors (U and SHGC rows are in the data, but the model
has no window construction yet), heated slabs, interior (non-perimeter) slab
edges, wall-type tags read off PDF legends, and Appendix A assemblies.
