# Schedule-truth recall diagnosis on the synthetic second dataset (#1322)

**Status:** report only. No parser change, no capacity-agreement change, no
truth-set change, no change to `mech_schedule.py`. Every number below comes
from a bench run made in this worktree against the synthetic second dataset
(`synth-office`, #1296).

## Method

- **Dataset.** `synth-office` from `scripts/benchmarks.json` — the second
  schedule-truth dataset (#1296, merged as PR #1302), generated by
  `scripts/make_synthetic_schedule_workbook.py` (seed 1296). Workbook:
  `~/workspace/datasets/matchline-bench/synth-office/synth-office.xlsx`,
  sha256 `ab30b5cce2e935cb9ff9c75f6c5790e44505a7f08a19422c92e8fd24de5dfc59`.
  Re-running the generator into `/tmp` reproduces the same sha256 byte for
  byte, so the on-disk dataset is current with the committed generator and
  the frozen truth (`truth.json`, same directory) is not stale.
- **Truth.** Frozen by `scripts/schedule_truth.py` (openpyxl only, never the
  extractor). The bench reports `truth: loaded` — the frozen file matches the
  workbook on disk.
- **Extractor.** `mech_schedule.parse_cobie_workbook` on the same workbook.
- **Scoring.** `scripts/schedule_bench.run_schedule_bench` (the same code
  path the CLI calls) — recall/precision, capacity, airflow, zone linkage,
  the category cross-tab (#1306) and the calibration table.
- **Missed-tag dump.** The bench JSON carries `tags.missed_sample` (the first
  ten missed tags, with name and type name) and `tags.missed_families_top`.
  On this dataset the missed total is 2, so `missed_sample` lists **every**
  missed tag — no separate dump path was needed. The per-row evidence
  (workbook row, sheet, tag-parse outcome, classification verdict, type
  description) was read with the repo's own readers: `parse_tag`,
  `classify`, `_text_type`, `TAG_PREFIX_TYPES` from `mech_schedule`, and
  `stated_values` from `scripts/schedule_bench`. The helper that printed it
  lives under `/tmp` and is not part of the diff.

## Missed tags

The missed total is **2** (`counts.missed_tags = 2`), against 18 truth rows
and 16 extractor rows: recall 0.889, precision 1.000.

| missed tag | truth row (workbook) | space | type name | why it is missed |
|---|---|---|---|---|
| `RCP-1` | Component row 3 | 1.01 | Duplex receptacle | tag parsed from the name, but no tag prefix and no text rule names a family → `classify()` = `(None, "none")` → the row is **excluded**, counted in `stats["excluded"]` |
| `FA-1` | Component row 4 | 2.01 | Fire alarm device | same: `classify()` = `(None, "none")` → **excluded** |

No missed tag is in the review queue (`review_items = 0`), and no missed tag
is a duplicate or an empty-tag row. The third excluded workbook row (row 5)
carries no tag at all, so it is not a truth row and not part of the missed
total (see dimension F).

The category cross-tab (#1306) collapses both misses into one row
(`Equipment: truth 18, matched 16, missed 2`), so it explains none of them.
The dimensions below are the ones the cross-tab does not carry.

## Ranked next hypotheses

Each hypothesis names how many of the **2** missed tags it would address and
a discriminating example by tag ID.

1. **The gap is a scope/allow-list decision, not a parse failure — 2 of 2
   missed tags (`RCP-1`, `FA-1`).** Discriminating example: `RCP-1` — the tag
   parses cleanly, the row is a well-formed `Component` row with a type
   description and a valid space, and `classify()` returns `(None, "none")`;
   the row is *excluded by design*, not lost. Test: add the two electrical
   families to the text/prefix evidence and re-run the bench — expect
   `missed_tags` 2 → 0, recall 0.889 → 1.000, and precision still 1.000
   against this truth set (the two tags *are* truth rows). The open question
   is scope, not measurement: a mechanical schedule that carries receptacles
   and fire-alarm devices is a product decision, not a parser fix.
2. **Truth-set scope mismatch — 2 of 2 missed tags (`FA-1`, `RCP-1`).** The
   truth reader counts every tagged `Component` row as a truth row, including
   electrical equipment that a mechanical schedule has no family for. The
   bench docstring already states this is intentional ("Missed truth tags are
   listed with their type names so exclusions (receptacles, doors) stay
   visible instead of silently deflating the score"). Discriminating
   example: `FA-1` — a fire alarm device, i.e. a truth row the mechanical
   extractor is not meant to carry. Test: filter the truth row set by family
   scope and re-run — expect recall 1.000 with the missed total at 0, which
   would make the remaining clinic-scale gap (not measurable here) a scope
   question rather than a recall question.
3. **Type-description evidence weight — 2 of 2 missed tags (`FA-1`,
   `RCP-1`).** Discriminating example: `FA-1` — its `Type` description
   restates the type name and contains no word any `TEXT_RULES` pattern
   matches, so the description channel is inert for both misses. Test: put a
   rule-matching word into those two `Type` descriptions (e.g. a description
   naming a family) and re-run; if the two misses become matches, the gap is
   a *text-rule coverage* gap, and if they stay excluded, the exclusion is
   by design and hypotheses 1/2 stand. This hypothesis separates the two
   readings of the same evidence.
4. **Tag-carrier dependence on the `Name` column — 0 of 2 missed tags.**
   Discriminating example: `RCP-1` — the `TagNumber` cell reads `n/a` and the
   tag exists only in the name, yet `parse_tag()` recovered it. All 18 truth
   rows are `tag_source = "name"`, and both missed tags parse, so this
   explains none of the misses; it is listed because it is the obvious
   remaining hypothesis on a workbook where every tag is name-borne.
5. **Untagged-row accounting — 0 of the 2 missed tags, but it moves the
   denominator.** Discriminating example: the untagged workbook row 5 (no
   tag ID: the motor control centre) — the truth records it as untagged with
   a reason, so it is excluded from the truth rows; the extractor excludes it
   too. Test: count untagged rows as misses — the missed total becomes 3 and
   recall 16/19 = 0.842.
6. **Multi-row layout (#1300) — 0 of 2 missed tags.** Discriminating
   example: none; there is no multi-row record in this workbook
   (`stats["continuation_rows"] = 0`), so the continuation-row reader cannot
   explain any miss here. The #1300 multi-row change is therefore not
   exercised by the synthetic dataset at all, which is why it moved the
   clinic numbers (0.270 → 0.273) but nothing here.

## Limitations / contradictions

- **The issue's numbers are not reproducible on this VM.** #1322 quotes
  precision 1.0 / recall 0.27 with 1520 tagged, 410 → 415 matched and ~1,100
  unmatched. Those figures describe the `bsi-clinic` dataset, whose workbook
  is absent here: the bench reports `bsi-clinic | missing — no schedule
  workbook on disk (see DATASETS.md)`. This note therefore decomposes the
  gap on the **synthetic** dataset only, where the missed total is **2**, not
  ~1,100. The clinic-scale gap cannot be categorised from this VM.
- **The synthetic dataset is small.** 18 truth rows, 2 misses: every count
  here is a count of 0, 1 or 2, so the categorisation is exhaustive but has
  no statistical weight. It is a *structure* diagnosis (which stage of the
  pipeline loses a tag), not an estimate of the clinic gap.
- **`uv` is unavailable** on this VM (see Method), so the runs used
  `python3` instead of `uv run --no-sync`.
- **No parser, truth or capacity change was made.** The hypotheses above are
  for the issue to triage; the only file added by this work is this note.
