### A seed bug that would have invalidated the whole experiment (`e2292dd`)

The 1-epoch validation pass exposed it: all three seeds returned **byte-identical**
metrics (baseline 0.05485, ECA 0.1874, to five decimals, for seeds 0/1/2).

Cause: `train.py` seeded `random`/`numpy`/`torch` from `args.seed`, but never passed
`seed=` to `model.train()`. Ultralytics re-seeds all three from *its own* `seed`
argument at the start of training, which overrides the earlier calls and falls back to
its default of `0`. So `--seed 1` and `--seed 2` were the same run as `--seed 0`, and
the "3 seeds" were one sample counted three times. Any delta from that matrix would
have been noise dressed as a result.

Fixed by forwarding `seed=args.seed`. Verified immediately after, 1 epoch, all else
identical: seed 0 → mAP50 0.05485, seed 1 → mAP50 0.20880. **A 15.4pt spread between
two seeds of the same config** — the clearest possible argument for the 3-seed rule.
`detector/tests` still 28 passed. The pre-fix summary was deleted, not archived as
data: its cross-seed agreement was the bug, not a finding.

**Lesson worth keeping:** a driver that reports three identical rows should be treated
as a failed experiment, not three confirmations. Identical numbers across seeds mean
the seed is not reaching the model, not that the effect is robust.
