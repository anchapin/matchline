`tests/test_detector_train_seed.py` — 8 tests, 0.2s, no GPU, no dataset, no
detector venv. The defect is pure argument forwarding, so `ultralytics` and
`torch` are stubbed in `sys.modules` (`train.py` imports both lazily inside
`main()`) and the kwargs passed to `model.train()` are inspected.

Four tests are not the obvious ones, and the reasons matter:

- **`test_seed_zero_is_forwarded_not_omitted`** — Ultralytics' own default is also
  `0`, so `kwargs.get("seed") == 0` passes on a train.py that forwards *nothing*.
  Only the key's presence distinguishes forwarded from omitted. This is the gap a
  naive `== seed` assertion leaves open.
- **`test_distinct_seeds_forward_distinctly`** — a hardcoded forward satisfies any
  single seed; 0/1/2 must forward as 0/1/2. This is the #500 driver-output shape,
  checked at the source instead of after four hours of GPU.
- **`test_python_level_seeds_still_applied`** — the `random`/`numpy`/`torch` calls
  that *made the original bug invisible* are pinned, so nobody "cleans up" the
  redundancy and re-breaks it.
- **`test_removing_the_kwarg_is_detected`** — defect injection. Writes a mutated
  **copy** of train.py to `tmp_path` and points the same assertion helper at it;
  asserts the helper raises. **The real train.py is never edited** — the obvious
  way to do this would have silently changed arms 2–6 of the running matrix.

**The location was the real finding.** The test went in `tests/`, not
`detector/tests/`: `detector/` is excluded from CI (`pyproject.toml:79`) and from
ruff, so a detector-only test is unenforced — which is precisely how 28 detector
tests passed identically before *and* after the seed fix. The defect needs no heavy
dependency, so it runs where CI enforces it. #507 (the other 28 tests) is
unaffected.

Also: seed contract written into `detector/README.md` where #500 gets reported —
**three identical rows in a summary mean a failed experiment, not three
confirmations** — plus the #509 caveat that 3 seeds understate variance, so a
within-arm spread is a floor, not a confidence interval. The stale "blocked on no
dataset" status paragraph there is now accurate.
