## 3a. A real bug CI caught, and why the local suite was not enough

The #502 commit went **red in CI while green locally** — 8 errors, all
`Both input arrays must be (arrays of) 3-dimensional vectors`, from
`geometry_simplify._douglas_peucker`:

```python
d = np.abs(np.cross(seg, pts[i0 + 1 : i1] - a)) / L
```

`np.cross` on 2-D vectors was deprecated in NumPy 2.0 and **raises** on >= 2.3. CI
installs `numpy` unpinned (`pyproject.toml` pins nothing) so it resolved to a raising
version; local development has 2.2.6 where the identical line only warns. The `dp_eps`
path had **no test coverage at all** before #502, so nothing had ever run it — the new
oblique fixtures are what surfaced it.

Fixed by writing the 2-D cross product out explicitly, verified **bit-identical** to the
old expression over 200 random cases (`max |old - new| == 0.0`), so it is a pure
compatibility fix. Suite warnings drop 56 → 14. `test_dp_pass_raises_no_deprecation_warning`
now runs the pass with `DeprecationWarning` promoted to an error so the two environments
cannot diverge silently again.

Worth remembering: local-green / CI-red on identical code was a *dependency* divergence,
not a flake. Any unpinned dependency is a latent version-dependent failure.
